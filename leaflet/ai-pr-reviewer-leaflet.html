AI Pull-Request Reviewer

On-demand AI code review for our Bitbucket pull requests — one verified, prioritized comment per review.
~3 min · ~€0.04
typical time & cost per review

START A review starts three ways

💬 Comment

Type /ai-review on the pull request. Add --force to re-review an unchanged head.

➕ Add reviewer

Add the AI reviewer user as a PR reviewer — the review starts automatically.

🚀 Open / ready

A non-draft PR opened, or a draft marked ready, with the AI reviewer among its reviewers — review starts.

Merge/backport PRs (e.g. develop ↔ release/*) are skipped. Only users on the allowlist can trigger.

READ How to read the comment

🔴
Do not mergecritical issues must be resolved
🟠
Do not mergehigh-severity issues found
🟡
Worth addressingbefore merge
✅
Nothing blocks mergelow-severity or clean
⚖️
Every finding is self-containedtitle + file:line · impact · verbatim evidence · suggested fix · "What's good" · Jira coverage (Met / Partial / Unmet / Not verified)
  • Three reviewers + consensus run in parallel (a 4th joins on translation PRs), then verify, dedupe and prioritize.
  • Severity: CRITICAL 🔴 · HIGH 🟠 · MEDIUM 🟡 · LOW ⚪ — below-threshold findings collapse under "Minor".
  • Evidence-grounded: checks (schema, line numbers, evidence, SHA) run as code, not in the prompt.
  • Published only for the reviewed revision — a changed PR never gets a stale report.
  • Translation PRs get a dedicated "Language & content" section — advisory below HIGH.

WHY What it gives us

For the team

  • Catches silent regressions before merge; consistent depth (security, concurrency, compatibility, Jira criteria)
  • A second pair of eyes, not a replacement — human review stays, on a verified baseline
  • Feedback in minutes, not "when someone gets to it"

For the business

  • Faster feedback → shorter cycle time, fewer late reworks; review capacity on demand, 24/7
  • Tiny footprint: one OpenShift pod + small volume; latency, cost and quality tracked per review
  • Teams can tune the reviewer per repo in plain markdown — no code change
